# PRD：qSOFA 計算

## Problem Statement

臨床人員在急診、病房或院前場域面對疑似感染的成人病人時，需要快速判斷病人是否較可能出現 Sepsis 的不良預後。qSOFA 只有三項床邊指標，但人工計分時容易在切點（RR 22、SBP 100）上算錯，也不容易一眼看出是哪幾項達標。

## Solution

提供一個 qSOFA 計算功能：輸入 Respiratory rate、Systolic blood pressure、GCS，回傳總分、是否陽性（≥2 分），以及每一項是否達標。輸入缺漏、不是數字，或 GCS 超出 3–15 時直接報錯，不回傳可能誤導的分數。

計分依 Sepsis-3（Singer et al., 2016）：

- Respiratory rate ≥22/min
- Altered mentation：本專案以 GCS <15 作為操作定義
- Systolic blood pressure ≤100 mmHg

## User Stories

1. 身為急診護理師，我想輸入 RR、SBP、GCS 就得到 qSOFA 分數，以便快速完成床邊評估。
2. 身為急診護理師，我想看到每一項是否達標，以便知道是哪個生命徵象異常。
3. 身為病房護理師，我想在分數 ≥2 時得到明確的陽性結果，以便依單位流程通知醫師。
4. 身為臨床人員，我想讓 RR 剛好 22/min 時算 1 分，以便符合 Sepsis-3 的切點。
5. 身為臨床人員，我想讓 SBP 剛好 100 mmHg 時算 1 分，以便符合 Sepsis-3 的切點。
6. 身為臨床人員，我想讓 GCS 低於 15 時算 altered mentation，以便有一致的判定標準。
7. 身為臨床人員，我想在三項都正常時得到 0 分且為陰性，以便排除誤報。
8. 身為臨床人員，我想在輸入缺漏或不是數字時收到錯誤，以便不會依錯誤分數做判斷。
9. 身為臨床人員，我想在 GCS 超出 3–15 時收到錯誤，以便發現輸入錯誤。
10. 身為開發者，我想透過單一函式取得完整結果，以便之後接到表單或 API。

## Implementation Decisions

- 一個 qSOFA 模組，對外只提供一個計算函式；輸入為含 `respiratoryRate`、`systolicBP`、`gcs` 的物件。
- 回傳 `{ score, positive, criteria }`：`score` 為 0–3 的整數；`positive` 在 `score >= 2` 時為 `true`；`criteria` 列出三項各自是否達標（`respiratoryRate`、`systolicBP`、`mentation`）。
- 任一輸入不是有限數字 → 丟出 `TypeError`。
- GCS 不是 3–15 的整數 → 丟出 `RangeError`。
- 使用 Node.js 內建 test runner（`node --test`），不加第三方套件；`npm test` 執行全部測試。

## Testing Decisions

- 好的測試只透過公開函式驗證外部行為：給定輸入，檢查回傳結果或錯誤類型，不測內部實作。
- **Seam**：唯一的 seam 是 qSOFA 計算函式本身。（依 CLAUDE.md，seam 直接採用此推薦，未停下確認。）
- 涵蓋：三項全正常、各項切點兩側（RR 21/22、SBP 101/100、GCS 15/14）、單項 1 分仍為陰性、2 分與 3 分陽性、非數字輸入、GCS 邊界（3 合法，2、16、14.5 報錯）。
- 期望值以 Sepsis-3 的切點為獨立依據，不在測試中重算公式。
- 專案為新建，沒有既有測試可參考。

## Out of Scope

- SOFA 完整計分、乳酸或其他檢驗值。
- RR、SBP 的生理範圍檢查（例如負值）：上下限屬臨床決策，留待後續定義。
- 使用者介面、表單、API。
- 兒童病人（qSOFA 為成人工具）。
- 依分數提供治療建議。

## Further Notes

- Surviving Sepsis Campaign 2021 建議不要單獨用 qSOFA 篩檢 Sepsis 或 septic shock，應優先使用 SIRS、NEWS 或 MEWS（Evans et al., 2021）。本功能僅作為預後風險的輔助計算。
